# NordSSH: требования к новому нативному клиенту

Дата: 2026-10-23. Основание: уточнения владельца и совместный разбор руководителя
архитектуры, QA и security-критика. Решение: новое приложение с нуля; старый
Tauri-прототип не переносится. Этот документ описывает требования, не готовые функции.

## Продукт и границы

NordSSH — бесплатный самостоятельный SSH/SFTP-клиент для Windows и Linux.
Исходники и готовые пакеты публикуются в GitHub NetGraniz/NordSSH.
Собственный код — MIT; зависимости сохраняют собственные лицензии.

В приложении нет HTML-интерфейса, JavaScript, Tauri, Electron, WebView2, WebKit,
Qt WebEngine и встроенного браузера. Пользователь не устанавливает Qt SDK,
Visual Studio, Node.js, Python, .NET или Rust. Нужные библиотеки входят в пакет.
Базовые API Windows, системные библиотеки и графическая среда Linux остаются
зависимостями ОС; обещания «работает на любой ОС вообще без зависимостей» нет.

Сохраняются понравившиеся композиция, тёмная палитра, зелёные акценты, карточки,
боковая навигация и вкладки. Рабочие экраны не содержат пересказа ТЗ, рекламных
плашек «без облачной учётной записи» или служебных статусов разработки.

| N01 | Нативное приложение | Запуск и SSH/SFTP на Windows без WebView2 и Linux без WebKit. Нет веб-движка в поставке и дереве процессов. |
| N02 | Установщики и portable | Windows per-user setup и ZIP; Linux .deb и portable AppImage/архив. Чистая установка, ярлыки, переустановка и удаление проверены. |
| N03 | Сохранённые подключения | Создание, изменение, удаление, поиск, группы и избранное. Изменение адреса/пользователя не переносит старый секрет незаметно. |
| N04 | SSH-аутентификация | Пароль; обычные и зашифрованные Ed25519/ECDSA/RSA-SHA2 ключи; OpenSSH user certificates; keyboard-interactive/2FA. Неверные данные можно исправить; подключение можно отменить. SHA-1 ssh-rsa не включается автоматически. |
| N05 | Доверие серверу | Адрес, порт, алгоритм и SHA256 видны в собственном диалоге приложения до аутентификации. Отмена/таймаут запрещают вход. Неожиданно изменённый ключ блокируется. |

| N07 | Сессии | Вкладки, подключение, отмена, переподключение, keepalive и корректное завершение. GUI не зависает при сетевых таймаутах. |

| N09 | Клавиатура и буфер | ПКМ, Ctrl+V, Ctrl+Shift+V и Shift+Insert вставляют один раз на RU/EN. Нет browser permission. Ctrl+C остаётся терминальным прерыванием; копирование имеет отдельную комбинацию. |
| N10 | Вставка команд | Bracketed paste учитывает режим терминала. Не добавлять Enter к обычной вставке. Подтверждение опасной многострочной вставки оформлено внутри приложения. |

| N14 | Настоящие vaults | Создание, открытие, переключение и блокировка отдельных зашифрованных файлов. У каждого свой случайный ключ и пароль. Группы серверов — отдельная сущность, не замена vault. |

| N22 | Практическая SSH-сеть | Для первого полноценного выпуска проверены jump host и local forwarding, с отдельными явными настройками и корректной отменой. Не запускать локальный shell из произвольного SSH config. |

## Безопасность и сохранность данных

- Доверие привязано к конкретной попытке соединения и именно полученному ключу.
  Ответ из другого/закрытого диалога не подходит. Параллельные подключения заново
  проверяют сохранённый ключ перед записью доверия.
- Серверный вывод — недоверенный ввод. OSC52 по умолчанию не получает доступ к
  clipboard; escape-последовательности не запускают программы и не открывают ссылки.
  Размеры parser buffers, очередей, экрана и scrollback ограничены.
- Удалённое чтение clipboard запрещено всегда. Разрешение OSC52-записи, если
  появится, будет отдельной opt-in настройкой, не побочным эффектом подключения.
- SFTP-имена не могут выходить из выбранной локальной папки; ссылки видны явно,
  рекурсивная операция не следует им незаметно. Overwrite использует staging и
  atomic rename при поддержке сервером; небезопасная подмена не служит fallback.
- Неявные SSH config/ProxyCommand/agent forwarding выключены. Local forwarding
  по умолчанию слушает только loopback, не все сетевые интерфейсы.
- Секреты не попадают в логи, argv, URL, Qt properties и незашифрованные экспорты.
  Криптографические буферы очищаются при освобождении; полной защиты от malware
  того же пользователя или администратора приложение не обещает.
- KDF и сетевые операции не выполняются в GUI-потоке. Нет QThread::terminate().
- Запись vault атомарная, с блокировкой файла и обнаружением внешних изменений.
  Импорт не интерпретирует ошибку чтения как пустой vault.
- Запоминание устройства не означает отсутствия шифрования. «Забыть устройство»
  удаляет локальную сохранённую копию ключа, но не отзывает уже украденный ключ.
- Подпись обновления и Windows Authenticode — разные механизмы. До получения
  настоящего сертификата нельзя обещать отсутствие SmartScreen.

## Матрица платформ

Начальная обязательная цель: Windows 11 x64, Windows Server 2025 Desktop Experience
x64 и Ubuntu 24.04 x64. Для Linux проверяются X11 и Wayland, включая clipboard/IME.
Windows Server без графической оболочки не является целью desktop UI.

Windows 10 x64 и Ubuntu 22.04 x64 включаются в список поддержки только после
отдельных прогонов и проверки выбранной версии Qt/glibc. ARM64, macOS и RPM
не объявляются поддержанными заранее. Архитектура не должна мешать их добавлению.
Точный Qt patch и бинарный baseline ещё не утверждены.

## Что не подменяет обязательный объём

Split panes, SSH agent, remote/dynamic forwarding, импорт PuTTY/OpenSSH config,
восстановление рабочих пространств и SFTP resume остаются расширениями следующего
этапа. Их отсутствие должно быть обозначено, а не замаскировано неработающей кнопкой.
Если владелец повысит приоритет, матрица меняется до разработки соответствующего UI.

Telnet, serial, Mosh, RDP, FIDO2, облачная синхронизация, командные аккаунты и AI
не входят в согласованный первый выпуск. Полный паритет со всеми версиями Termius
не обещается. Чужие бинарники, иконки и код не копируются.

## Старый прототип

По решению владельца от 2026-10-23 новый клиент не переносит старую реализацию.
Существующие vault, резервные копии и signing keys не удаляются и не перезаписываются.
У нового клиента отдельный data namespace и явно отличающийся формат файла.
Автоматического чтения/миграции старой беты нет. Будущий мигратор — отдельная задача.
